CHAPTER 01

What is an algorithm?

The plan

An algorithm is a finite, ordered set of clear instructions that solves a problem. It takes some input, transforms it through a process, and produces an output.

A good algorithm is precise (no guesswork), finite (it eventually stops), and effective (each step can actually be carried out). Before coding, make sure you understand the problem and what counts as a correct answer.

1. Input

The information the problem gives you.

2. Process

The operations and decisions that transform the input.

3. Output

The result the algorithm must produce.

Example · Add two numbers

For inputs 4 and 7, add them and show 11. Pseudocode describes the logic without tying it to a programming language.

START
  READ a, b
  total ← a + b
  DISPLAY total
END
CHAPTER 02

Variables, decisions & loops

The tools

A variable is a named place to store a value that an algorithm can use or update. Its type tells us what kind of value it holds: for example, an integer, a decimal number, or text.

Algorithms change their path with a condition and repeat work with a loop. Use a condition when the next step depends on a test; use a loop when an action must happen again. Always check that a loop can reach its stopping condition.

Example · Sum from 1 to n

A loop adds each number to a running total. Try a value from 1 to 100 and watch the result.

1 + 2 + 3 + 4 + 5 = 15
total ← 0
FOR number ← 1 TO n
  total ← total + number
DISPLAY total

To reason through the example for n = 3: start with total = 0; add 1 (total = 1); add 2 (total = 3); add 3 (total = 6). This step-by-step trace is called a dry run. It helps catch logic mistakes before you write or run code.
